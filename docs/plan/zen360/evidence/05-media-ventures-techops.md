## Advisor notes (what the proposal misses)

- **Ventures need a separate Experiment entity, not more initiative statuses.** Suggested fields: `id`, `recordCode`, `ventureId`, `question`, `hypothesis`, `testDesign`, `successMetric`, `stopCriterion`, `budgetCeilingPaise` (bigint), `capacityHours`, `sponsorPartyId`, `reviewDate`, `status` (proposed, approved, running, passed, failed, stopped), `evidenceDocumentIds`, `decisionNote`. Controls: `assertCan` on a new `ventures` resource; approval via ApprovalStep (main.prisma:810); `auditWrite` after registering `venture`, `experiment`; `emit` with past-tense names; tenant scope from session. Dependencies: Phase 1 for money, Phase 2 for audit retention. Size L across the venture set.
- **A failed experiment is a record, not a deletion.** Use `stopped` or `failed` as terminal states. Hard delete is prohibited in the audit path (CLAUDE.md Never).
- **Customer discovery is personal data.** Interview notes identify people. Consent and notice must precede capture (docs/plan/archive/phase-2-audit.md:22-26). Store interview records under a purpose code, and make withdrawal suppress future use.
- **Research assistant is the only place an AI model would touch external content.** The model gateway (platform/llm.ts) is policy and types only; the proposal's "AI research assistant" would be the first provider call. Its tasks list (llm.ts:16) has no research task. Output must be drafts for human review (shared/ai.ts DRAFT tier). If any personal data reaches a provider, `applyFieldVisibility` and India-region rules apply (CLAUDE.md, llm.ts:103).
- **Grant calls need immutable versions.** A grant's eligibility can change between discovery and submission. Use snapshot records (EntitySnapshot pattern, main.prisma:2587). Deadline stored as UTC; displayed in IST via time.ts.
- **Name collision.** `Grant` (main.prisma:744) is an access grant. Any funding model must use a different name, and the audit registry already holds `grant` under `gov` (platform/audit.ts list). Flag before the funding model is named.
- **MSP needs a tenancy decision before a schema.** The platform is one tenant per company (CLAUDE.md Rule 6; platform/db.ts). Serving external customers either makes each customer a tenant, which breaks cross-customer shared staff and billing, or puts a customer dimension inside one tenant, which needs record-scope rules. platform/recordScope.ts must be extended, not rewritten. Decide first (D1).
- **Monitoring integration is an inbound trust boundary.** An alert webhook is unauthenticated input until its signature is checked. The tenant must come from the endpoint credential, not the payload. Dedupe on a fingerprint. Customer infrastructure monitoring must not start until authorisation is contractual and a runbook is tested (proposal p23 says so; no code enforces it).
- **Subscriptions are money plus time.** Metered usage needs append-only events, IST cut-offs (time.ts:21-32) and adjustments through approval. Overdue status must never disable access automatically (T-09 keeps this true today; add the test).
- **Statutory points flagged, not decided (counsel to confirm before any StatutoryRule is written):**

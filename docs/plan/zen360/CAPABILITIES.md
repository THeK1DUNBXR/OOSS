# CAPABILITIES — proposal capability set as a build register

Source: findings 01–12 (proposal pp. 4–68, 75) checked against the repo. Statuses are against code as it is on the checked-out branch. Nothing under /home/user/OOSS was changed.

**Reading the table.** Status = EXISTS (works for the proposal's purpose, possibly with a FIX noted), PARTIAL (some of the mechanism runs), MISSING (no model/route/UI, or schema with no writer). Evidence = the single best `file:line`; paths are repo-relative (`main.prisma` = `apps/api/prisma/schema/main.prisma`). ⚠️ = statutory or legal uncertainty: stop and flag, never encode a constant (CLAUDE.md rule 4 and "Statutory uncertainty").

**Dependency shorthand.** `P0`–`P8` = plan phases in `docs/plan/` (P1 = ledger, P1.6 = money helper, P2 = audit spine + DPDP, P3 = statutory, P4 = interface incl. 4.2a Metric union, P5 = semantic, P6 = intelligence, P7 = product/tenancy, P8 = proof). `CEO-n` = phase n of `docs/plan/ceo-office.md`. `D-nn` = row in DECISIONS.md. `FX:<topic>` = a FIX row owned by the other agent that must land first (e.g. `FX:audit-registration` = register the entity with `registerGovernedEntities`; `FX:money` = Decimal/number money columns; `FX:scope` = unscoped list reads / record scope; `FX:perm` = route with no `assertCan`; `FX:ist` = UTC period maths; `FX:ai-fence` = agent tier/prohibition bypasses; `FX:consent-gate` = inert `requiredConsent`; `FX:integrity` = event-chain verifier; `FX:imports` = import commit/revert defects). Sizes: S under 1 wk, M 1–3 wk, L over 3 wk (one engineer, estimate only).

**Global constraints on every row marked "add".** New money columns are bigint paise (rule 1, P1.6); journal effects only via `platform/ledger.ts` `post()` (rule 2); IST periods via `packages/shared/src/time.ts` (rule 3); statutory parameters as `StatutoryRule` rows (rule 4); each write is `assertCan` then write then `auditWrite` then `emit`, with the entity registered via `registerGovernedEntities` (rule 5); tenant from session (rule 6); every shown number has `drillTo` or a truthful `noActionReason` (rule 7). These are not repeated per row.

**Two facts that gate half the register.** (1) `platform/ledger.ts` `post()` has no caller: every money movement lands in the legacy `Transaction` table and all reports read it (`platform/ledger.ts:61`, `domains/books.ts:1165`). (2) Zero model calls exist in the repo (`platform/llm.ts:220-230`), so every AI row is a policy label until a provider adapter is built.

# Making execution cheap

Read once, by whoever sets the repo up. After that `CLAUDE.md` carries the rules and the tooling enforces them.

The plan itself is not where the money goes. Executing it is. Below is where this specific repository leaks tokens, with the fix for each — ordered by how much each one costs.

---

## 1. `schema.prisma` is 4,031 lines, and almost every task touches it

A single read is roughly **40,000 tokens** — more than a whole phase file, for a task that usually needs one model. And it is not a one-off: Prisma work reads it, then reads it again after an edit, then again next session.

**Fix: split it.** Prisma 6.1 (this repo's version) supports a schema folder. Move `apps/api/prisma/schema.prisma` to `apps/api/prisma/schema/` with one file per bounded context — `identity.prisma`, `crm.prisma`, `finance.prisma`, `education.prisma`, `hr.prisma`, `platform.prisma`, `books.prisma`, `imports.prisma`. Prisma concatenates them; nothing else changes.

```jsonc
// apps/api/package.json
{ "prisma": { "schema": "prisma/schema" } }
```

A finance change then reads ~400 lines instead of 4,031. This is the single largest saving available in the repository and it is an afternoon's work. **It belongs in Phase 0**, before the ledger work in Phase 1 starts reading that file forty times.

Two smaller siblings, both now denied by `.claude/settings.json`: `pnpm-lock.yaml` (5,152 lines, answers nothing) and `src/tests/fixtures/demoDataset.ts` (1,916 lines of seed data an agent should never need to read whole).

## 2. Exploratory search — "let me understand the codebase first"

The expensive pattern is not one bad grep. It is the opening move of every session: a few `grep`s and a few whole-file reads to locate something the repository already knows the answer to.

**Fix: `docs/plan/MAP.md`**, generated by `node scripts/genmap.mjs`. It is a 240-line index of every Prisma model, every exported symbol in the API domains, platform, imports, jobs and shared packages, every HTTP route, and every web page — each with `file:line`, and each file's line count so the agent can judge before opening it.

Looking something up in MAP costs ~2,000 tokens once per session and replaces the searching entirely. `/where invoice` does the lookup.

A stale map is worse than none, so `genmap.mjs --check` runs in CI and fails the build on drift. Regenerate it whenever the schema or a domain's exports change — it is part of the change, like a migration.

---

## 3. Reading whole files to change thirty lines

`domains/invoicing.ts` is 1,540 lines. `createForms.tsx` is 1,898. `PeopleOps.tsx` is 1,537. `acceptance.test.ts` is 2,461. Opening any of them whole to make a local edit costs 15–25k tokens for perhaps 300 tokens of relevant context.

**Fix, as a standing rule:** MAP gives the line, `Read` takes `offset` and `limit`, and `Edit` takes a string rather than a rewrite. Reserve `Write` for genuinely new files — rewriting a 1,500-line file to change one function pays for the whole file twice, once to read and once to emit.

---

## 4. The test suite is 372 tests, serial, against a real Postgres

That serialisation is deliberate and correct — gapless record codes and hash-chain continuity are claims about ordering, and a parallel runner would be asserting something else. But running the whole suite after every small change is slow, and its output lands in context.

**Fix: scoped scripts and a quiet reporter.**

```jsonc
// apps/api/package.json — add
"test:books":     "vitest run src/tests/books.test.ts --reporter=dot",
"test:invoicing": "vitest run src/tests/invoicing.test.ts --reporter=dot",
"test:hr":        "vitest run src/tests/hr.test.ts src/tests/hrLifecycle.test.ts --reporter=dot",
"test:quick":     "vitest run --reporter=dot --bail=1"
```

Run the narrow one while iterating; the full suite once before the PR. `--reporter=dot` turns hundreds of passing lines into dots, and `--bail=1` stops at the first failure instead of printing the other 371 results.

The same applies to every noisy command. `pnpm typecheck` on a failure prints the full program; pipe it:

```bash
pnpm typecheck 2>&1 | grep -E "error TS|Found [0-9]+ error" | head -30
pnpm build 2>&1 | tail -20
```

`/check` does both with the truncation already applied.

## 5. Re-deriving what the plan already states

The phase files give exact line numbers. An agent that re-audits the repository to confirm them has paid twice for the same fact.

**The rule:** confirm one line with a targeted `grep -n`, not a survey. If it does not match, `README.md` has the known drift table — check there before concluding the plan is wrong about the file.

The corollary matters more: when a claim about existing code *is* load-bearing, cite `file:line` and confirm it. Roughly one description in ten is of code that would be reasonable rather than code that is there — which is how the `Metric` error got into this plan in the first place. Confirming one line is cheap; building on a wrong one is not.

## 6. Search results landing in the main context

A fan-out search — "find every call site of X", "which files do Y" — dumps file excerpts into the window and keeps them there for the rest of the session, even though only the conclusion mattered.

**Fix: delegate it.** Send it to a subagent and ask for the conclusion, not the files. The excerpts die with the subagent; the answer comes back in a paragraph. Use this for anything that would touch more than three or four files, and say explicitly in the prompt: *return conclusions with `file:line`, not file contents.*

---

## 7. Carrying a finished phase into the next one

Context does not get cheaper by being reused when the reuse is irrelevant. Carrying a completed Phase 1 through Phase 3 means paying for the ledger conversation on every turn of the statutory work.

**Fix: `/handoff` then `/clear`.** `/handoff` writes `docs/plan/HANDOFF.md` — items done, items not done and why, decisions taken that aren't in a file, plan claims found wrong, and the single next action, all under 300 words. The next session reads that instead of reconstructing state, and starts near-empty.

Corollary: **stop and report rather than half-finishing.** A half-converted `DataTable` migration costs more to diagnose and recover than to redo. When context runs short, say what is left — that is what HANDOFF is for.

---

## 8. Narration

Explaining what it is about to do, then doing it, then summarising what it did, triples the output tokens on every step. Output tokens cost more than input.

Already in `CLAUDE.md`: say what changed at the end. The tool calls are visible; the running commentary is not information.

---

## What this adds up to

| Leak | Fix | Saves |
|---|---|---|
| `schema.prisma` read whole | Split to `prisma/schema/` | ~35k per read, many reads |
| Exploratory search | `MAP.md` + `/where` | 5–20k per session |
| Whole-file reads | MAP line numbers + `Read offset/limit` | 10–25k per edit |
| Full suite, verbose | Scoped scripts + `--reporter=dot` | 2–8k per run, many runs |
| Fan-out search in main thread | Subagent, conclusions only | 5–30k per search |
| Carrying finished phases | `/handoff` + `/clear` | Compounds every turn |

None of it is a trick. It is the same discipline as not `SELECT *`-ing a table to read one column.

## Setup checklist

Once, before Phase 0:

- [ ] Copy `CLAUDE.md` to the repo root, `docs/plan/` and `scripts/genmap.mjs` into place.
- [ ] Copy `.claude/settings.json` and `.claude/commands/` in. Commit both — they are team config, not personal.
- [ ] `node scripts/genmap.mjs` and commit `docs/plan/MAP.md`.
- [ ] Add the scoped test scripts to `apps/api/package.json`.
- [ ] Add `node scripts/genmap.mjs --check` to CI (Phase 0.7).
- [ ] Split `schema.prisma` into `prisma/schema/` (Phase 0).

Four commands are then available in any session: `/where`, `/check`, `/finance-pr`, `/handoff`.

# Sequencing and staffing

With Kaizen's stated model — four developers shifting to guiding and reviewing AI-written code from student interns — the realistic shape is:

- **Phase 0** is one senior developer, one week. Nothing else starts until it is merged.
- **Phase 1** is the most senior person available plus Claude Code, working alone, for a month. **Do not parallelise the ledger.** It is the one thing where a wrong decision compounds.
- **Phases 2, 3 and 4 run in parallel** after Phase 1 merges — compliance, statutory and interface are genuinely independent, and Phase 4 is the one interns can be most productive on because the failure mode is a bad-looking table rather than a wrong number.
- **Phase 5** needs the person who understands the domain vocabulary, not the best engineer.
- **Phase 6** starts only after 1, 2 and 5 are merged, and starts with §6.3, the Briefing.
- **Phase 7** starts when a second tenant is real.
- **Phase 8** is everyone, always.
